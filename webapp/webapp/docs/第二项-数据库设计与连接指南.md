# 数据库设计与功能对应

项目使用 MySQL，初始化脚本为 `sql/volunteer_star.sql`。数据库保留 14 张核心表，覆盖当前页面和后台接口。

## 1. 核心表

| 模块 | 数据表 | 用途 |
|---|---|---|
| 用户与区域 | `volunteer_user` | 登录注册、用户资料和角色 |
| 用户与区域 | `volunteer_region` | 活动区域和区域统计 |
| 活动基础 | `volunteer_organization` | 活动发布组织 |
| 活动基础 | `volunteer_tag` | 活动分类与分类颜色 |
| 活动基础 | `volunteer_activity_status` | 活动状态字典 |
| 活动基础 | `volunteer_activity` | 活动内容、时间、地点和容量 |
| 报名参与 | `volunteer_activity_enrollment` | 报名、审核、取消和完成状态 |
| 报名参与 | `volunteer_activity_sign` | 签到、签退和实际时长 |
| 服务时长 | `volunteer_service_hour_summary` | 用户累计时长和完成活动数 |
| 服务时长 | `volunteer_service_hour_change` | 每次时长变更明细 |
| 统计分析 | `volunteer_home_stat_snapshot` | 平台累计指标 |
| 统计分析 | `volunteer_region_stat_snapshot` | 区域活动与热度统计 |
| 统计分析 | `volunteer_category_stat_snapshot` | 活动分类统计 |
| 统计分析 | `volunteer_monthly_stat_snapshot` | 月度趋势统计 |

## 2. 页面对应关系

- `login.jsp`：读取和写入用户表。
- `activities.jsp`、`discover.jsp`：读取活动、分类和状态；报名写入报名表。
- `dashboard.jsp`：读取当前用户的报名、时长汇总和时长明细。
- `admin.jsp`：管理活动，审核报名，处理签到签退并更新服务时长。
- `heatmap.jsp`：保持原有页面实现；区域和统计表为后续数据库统计提供结构。

## 3. 报名流程

1. 用户打开活动报名卡片并确认报名。
2. 报名表写入状态 `0`，表示待审核。
3. 个人中心显示该活动和待审核状态。
4. 管理后台按状态查询并审核报名。
5. 审核通过后状态改为 `1`，同时创建签到记录。

## 4. 签到和时长流程

1. 审核通过的报名可以签到。
2. 签退时保存实际服务时长。
3. 系统把报名状态改为已完成。
4. 系统新增一条时长明细，并更新用户时长汇总。

## 5. 运行步骤

1. 启动 MySQL。
2. 备份已有数据后执行 `sql/volunteer_star.sql`。
3. 检查 `src/main/resources/jdbc.properties` 中的连接信息。
4. 使用 Maven 打包或在 IDEA 中部署 Tomcat。

数据库的完整字段说明和关系设计见桌面 `智能体` 目录中的《志愿星河数据库设计文档_14表版》。
